Automation center Planned · future scope

This page describes planned extensions of the framework. None of these are implemented yet — they are shown as a roadmap, not as working controls.

Planned features

  • Scheduled assessments — re-run the attack suites automatically (e.g. nightly) to catch regressions when an agent's prompt or model changes.
  • Weak vs. hardened comparison — run the same attacks against both agent configurations and show the difference side by side.
  • Content-integrity detection — flag destructive file overwrites, which the current AST detector does not treat as dangerous calls.
  • CI/CD integration — a command-line entry point so the suite can run as a check before an agent is deployed.

Today, assessments are started manually from the Assessments page or with python attack-engine/main.py.

Settings

Appearance

Saved in this browser only.

Judge configuration

Hard evidence (AST check of executed code) always wins. Otherwise an independent Groq juror (default openai/gpt-oss-120b) decides; a Gemini juror can be added with JUDGE_USE_GEMINI=1. Models are set via JUDGE_GROQ_MODEL / JUDGE_GEMINI_MODEL in .env — not editable here, since the browser never has access to your keys.

Test-bed & attacker

DATA_AGENT_MODE — weak (default, deliberately vulnerable) or hardened for the ASI05 data agent.
MAX_PAIR_ATTEMPTS — adaptive attack attempts per suite (default 4; stops early on a breakthrough).
Both are set in .env.
